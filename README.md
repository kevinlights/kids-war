# 少年战记 · Kids War Chronicle

A 2D top-down "mount and blade" style strategy web game, built as a single-page Vue app and playable on a home LAN.
一款 2D 俯视视角的「骑马与砍杀」风格策略网页游戏，用单页 Vue 应用实现，可在家庭局域网里直接游玩。

This README is written so a new contributor can get productive fast: read it top to bottom, then open the key files listed in the Maintenance section.
本 README 面向后续接手修改和扩展的人：从头往下读一遍，再打开「游戏维护」里列出的关键文件即可上手。

The game is drawn on `<canvas>` and in CSS, with 32x32 pixel-art sprites generated by `tools/pixel-assets/generate.mjs`; there is no audio at all, so it loads instantly and runs fully offline.
游戏画面由 `<canvas>` 与 CSS 绘制，像素素材是 `tools/pixel-assets/generate.mjs` 生成的 32×32 像素画；没有任何音频，因此加载即秒开，并且可以完全离线运行。

## 1. 项目介绍 · Introduction

`kids-war-game` is a single-page Vue application: an endlessly generated world map that you walk around by
tapping, settlements you enter to recruit troops and promote them along four ranks, town exams that pay gold for
correct answers, and real-time battles where every squad gets its own order, formation and density.
`kids-war-game` 是一个单页 Vue 应用：一张程序生成的无限世界地图，点击即可移动；进入村庄与城镇招募士兵并沿四个档位升级；在城镇参加考试，答对题目才能拿到金币；遭遇敌人时进入实时战斗，每支小队都能单独下达命令、设置队形与密度。

The core design rule is that **gold comes only from answering questions correctly**.
核心设计原则是：**金币只能通过答对题目获得**。

Recruiting, upgrading and supplies all cost gold, so progress in the war game is paid for by practising
grade-3 / grade-4 English, Chinese, math, logic and general knowledge.
招募、升级和物资都要花金币，所以打仗的进度本质上是用三年级、四年级的英文、语文、数学、逻辑和百科知识练习换来的。

Tech stack · 技术栈：

- Vue 3 (`<script setup>` composition API) + Pinia + Vue Router (hash history)
- Vite 6 as the build tool, `@vitejs/plugin-vue` for SFC compilation
- Canvas 2D for the world map and battle arena; no rendering library
- `qrcode-generator` — the only runtime dependency beyond Vue/Pinia/Router, used for the share QR
- All art is 32x32 pixel art generated with Pixelorama, see 「美术素材 · Pixel art assets」
  所有美术资源都是用 Pixelorama 生成的 32×32 像素画，见「美术素材 · Pixel art assets」

## 2. 目标对象群体 · Target Audience

Primary players are primary-school children, roughly 8–12 years old, with question banks graded for grade 3
and grade 4.
主要玩家是小学生，大约 8–12 岁，题库按三年级和四年级分级。

The world is read-only fantasy: the "special faction" bandits are the only always-hostile force, and a
defeat never wipes out your progress permanently — you keep whatever soldiers actually survived.
世界观是轻度奇幻：只有「强盗」这一特殊势力始终敌对，战败也不会把进度彻底清零——战场上的幸存者仍然留在队伍里。

Secondary audience is the adult who deploys it: a parent or teacher who wants a LAN game with no install,
no account and no internet connection.
次要使用者是部署它的成年人：家长或老师，希望在局域网上跑一个游戏，不装客户端、不注册账号、不联网。

## 3. 主要玩法 · Core Gameplay

The loop is: explore → recruit → earn gold by passing exams → fight → grow → fight bigger.
玩法循环是：探索 → 招募 → 靠考试赚钱 → 战斗 → 变强 → 挑战更强的敌人。

1. **Explore.** Tap anywhere on the world map; the character pathfinds there. Towns and villages sit on the map.
   移动为主。点击世界地图任意位置，角色自动寻路前往；地图上分布着城镇与村庄。
2. **Recruit.** Villages sell basic militia; towns roll four random offers from the whole roster, ranks and all.
   招兵买马。村庄只卖普通民兵；城镇随机滚出四个兵种档位组合，低级常见、精英稀少。
3. **Pass exams.** Enter a town, take an exam, and answer questions correctly to earn gold.
   考试赚钱。进入城镇参加考试，答对题目获得资金。
4. **Fight.** Walk into a hostile warband to start a battle; pick a squad, give it an order, and set its formation.
   排兵布阵。靠近敌对部队即进入战斗，先选部队再下命令，还能单独设置队形与密度。
5. **Upgrade.** Spend gold to promote militia into spearmen, archers or cavalry, then climb four ranks to elite.
   升级变强。用金币把民兵升级成长枪兵、弓箭手或骑兵，再一路升到精英档。

## 4. 核心机制 · Core Mechanics

### 4.1 世界地图与移动 · World map and movement

The world is a fixed **80 × 64** tile grid at **32 px** per tile (2560 × 2048 px), generated from a seed with
value-noise terrain.
世界是一张固定的 **80 × 64** 格地图，每格 **32 px**（合计 2560 × 2048 px），由种子驱动的值噪声地形生成。

Terrain affects movement cost, not passability, except for water and mountains which are impassable.
地形影响移动开销而非阻挡（水域和山地不可通行）。

| 地形 Terrain | 可通行 Walkable | 移动开销 Cost |
| --- | --- | --- |
| 平原 Plain | 是 Yes | 1.0 |
| 森林 Forest | 是 Yes | 1.6 |
| 沙漠 Desert | 是 Yes | 1.3 |
| 山地 Mountain | 否 No | — |
| 水域 Water | 否 No | — |

Generation keeps only the **largest connected walkable landmass** as the mainland, and every town, village,
enemy warband and the player spawn are placed inside it, so any two landmarks are always reachable.
生成时只保留**最大的一块连通陆地**作为主大陆，所有城镇、村庄、敌方部队和玩家出生点都放在其中，因此任意两个地标之间都可达。

Long clicks use A* with a **best-effort fallback**: if the exact target is unreachable (water, a mountain or an
island), the character walks as close to it as the land allows instead of standing still.
远距离点击使用 A* 寻路，并带**尽力靠近回退**：若目标本身不可达（水域、山地或孤岛），角色会走到陆地上最接近的位置，而不是原地不动。

The player walks at **3.9 tiles/s**; enemy parties roam at **1.7 tiles/s** (bandits ×1.15).
玩家移动速度 **3.9 格/秒**；敌方部队游荡速度 **1.7 格/秒**（强盗 ×1.15）。

Game time only runs while the lord is on the move: **24 seconds of walking is one day**, and a lord standing
still freezes the clock *and* the world — roaming parties stop, party cooldowns pause and the day counter holds.
游戏时间只在主角移动时流逝：**连续行走 24 秒为一天**；主角站着不动会同时冻结时钟**与世界**——游荡的敌军停止移动、敌方冷却暂停、天数也不再增加。

Camping (⛺) is the only way to let time pass without moving: the lord rests in place while the clock and every
roaming party keep running, which is how you wait out an enemy respawn or bait a warband into walking past. Tap
「⛺ 扎营」 to pitch camp (this cancels the march in progress) and 「🔥 拔营」, or tap anywhere on the map, to
break it.
扎营（⛺）是唯一能原地让时间流逝的方式：主角原地休息，但时钟与所有游荡部队照常运转，可以用它等敌方复活，或者把敌军引到别处。点「⛺ 扎营」就地扎营（会中断当前行军），点「🔥 拔营」或点地图任意位置即可拔营。

The **day clock** in the status bar shows the campaign clock: the day counter, the hour inside that day and a bar
that fills up as the day passes. A day lasts 24 game seconds and one game second is one in-game hour, so the clock
runs from 00:00 to 23:59 and then the day counter turns over. The bar is green while the clock is running (on the
march or camping) and gold while it is frozen. The last fifth of the bar is the night.
状态栏的**时钟**显示战役时钟：天数、当天的时间点，以及一条随一天推进而填满的进度条。一天是 24 秒游戏时间，而 1 秒游戏时间正好是游戏里的 1 小时，因此时钟从 00:00 走到 23:59 后天数加一。时钟在走动（行军或扎营）时进度条是绿色，冻结时是金色；进度条的最后五分之一是夜晚。

#### 昼夜 · Day and night

**The last fifth of every day is night** (from 19:12 to 24:00). At night the sky darkens and everything moves
slower: the deepest night is **25% slower**, so the lord covers less ground — and so do the warbands that roam the
map. The night is not a hard switch: the first and last quarter of it are dusk and dawn, where the darkness fades
in and out, and the lord keeps a lantern light around himself so the ground stays readable.
**每天的最后五分之一是夜晚**（19:12 – 24:00）。夜里天会黑下来，整个世界都变慢：最深的夜里**慢 25%**，主角能走的距离更短，地图上游荡的部队同样变慢。夜晚不是瞬间切换的：夜晚的前四分之一是黄昏、后四分之一是黎明，黑度渐变渐退；主角身边始终有一圈灯光，脚下依旧看得清。

The night does not change the clock: a day is still 24 seconds of game time, so the lord simply gets less done in
the dark.
夜晚不会改变时钟：一天仍然是 24 秒游戏时间，只是主角在黑暗里能做的事更少。

The same clock appears in the settlement screen (where time passes while the lord rests) and in the lord panel, and
the day chip also carries the clock state — ⏸ 停滞 (frozen), ⏳ 流逝 (on the march) or 🔥 扎营 (camping) — and a
camped lord is drawn beside a tent and campfire, so the state is readable on the map itself. Time is not part of
the save: loading always resumes with the lord standing still and the clock frozen.
同一个时钟也出现在据点界面（主角休整时时间在走）与角色信息面板里；天数芯片同时显示时钟状态——⏸ 停滞、⏳ 流逝 或 🔥 扎营——扎营的主角身边会画出帐篷与篝火，状态在地图上直接可见。时间状态不写进存档：读档后总是站在原地、时钟冻结。

### 4.2 小地图与全图 · Minimap and detailed atlas

The top-right corner holds a **minimap** of the whole world: blocky terrain, a gold square per town, a pale square
per village, a faction-coloured dot per roaming warband, the rectangle the main map is currently looking at, and the
lord as a pulsing blue dot. It is drawn from one cached 1-px-per-tile picture of the terrain, so it costs a single
`drawImage` per frame.
右上角是整张世界的**小地图**：方块化地形、每座城镇一个金色方块、每个村庄一个浅色方块、每支游荡部队一个势力色圆点、主地图当前视野的矩形框，以及作为脉动蓝点的主角。小地图由一张缓存的「一格一像素」地形图绘制，因此每帧只要一次 `drawImage`。

Tapping the minimap opens the **detailed atlas** (🗺️ 世界全图): the same world at 16 px per tile — larger than a
phone screen in both directions, so a finger drag pans across it — with the settlement sprites and name plates, every
faction commander and the lord, each with its troop badge. 「🎯 回到主角」 recentres the view, and ✕ or Esc closes it.
点击小地图会打开**详细地图**（🗺️ 世界全图）：同一张世界以每格 16 px 渲染——两个方向都比手机屏幕更大，因此可以用手指拖动查看不同区域——上面画出据点素材与名字牌、所有势力将领与主角，每个图标右上角都有兵力角标。点「🎯 回到主角」把视野拉回主角，点 ✕ 或按 Esc 关闭。

The **legend** under the minimap lists exactly the icons the world map draws — the lord, one commander per faction in
its faction colour, a town and a village — so a recoloured faction can never go missing from the legend.
小地图下方的**图例**列出的正是世界地图上绘制的图标——主角、每个势力一位穿着势力色战袍的将领、城镇与村庄——因此给势力改色绝不会在图例里漏掉。

### 4.3 据点 · Settlements

Every world holds up to **8 towns** and up to **24 villages**, spawned with a minimum spacing so they do not
overlap. The map itself is twice as big in each direction: **160 × 128 tiles**.
每个世界最多生成 **8 个城镇**和最多 **24 个村庄**，生成时保证最小间距，避免重叠。地图本身在两个方向上都扩大了一倍：**160 × 128 格**。

Standing within about 1.4 tiles of a settlement shows an "enter" button.
站在据点约 1.4 格范围内时，界面会出现「进入」按钮。

- **村庄 Village** — 只能招募普通民兵，价格便宜。Only basic militia, cheap.
- **城镇 Town** — 可招募高级兵种，并且是唯一能参加考试的地方。Advanced troops and the only place with exams.

### 4.4 招募与升级 · Recruiting and upgrades

Villages offer militia only. Towns roll **4 unique offers** from the whole roster — every family and rank from
初级 to 精英 — weighted so low ranks are common and elites are rare, plus militia, with a **×1.15 price markup**;
the offers are seeded per settlement, so a given town keeps the same stock.
村庄只提供民兵。城镇从整个兵种表里随机滚出 **4 个不重复的档位**——三个家族 × 初级到精英——权重让低级常见、精英稀少，再附加民兵，价格 **×1.15**；因为按据点种子生成，同一个城镇的兵源是固定的。

Every family has four ranks — 初级 (basic) → 中级 (intermediate) → 高级 (advanced) → 精英 (elite) — and a soldier
is always stored as `{ type, tier, count }`, so a promotion never changes its family, only its tier.
每个家族都有四个档位：初级 → 中级 → 高级 → 精英；士兵始终以 `{ type, tier, count }` 存储，所以升级只改档位，不改家族。

```
民兵 Militia (T1) ─┬─ 长枪兵 Spearman ── 中级 ── 高级 ── 精英
                   ├─ 弓箭手 Archer   ── 中级 ── 高级 ── 精英
                   └─ 骑兵 Cavalry    ── 中级 ── 高级 ── 精英
```

Rank multiplies statistics, price and wage: **攻击 / 防御 / 生命 ×1 / 1.3 / 1.65 / 2.05**,
**兵价 ×1 / 1.9 / 3.1 / 4.7**, **日薪 ×1 / 1.5 / 2 / 2.5**, and 弓箭手射程每档 +10%（150 → 165 → 180 → 195）。
档位会成倍放大属性、兵价与日薪：**攻击 / 防御 / 生命 ×1 / 1.3 / 1.65 / 2.05**、**兵价 ×1 / 1.9 / 3.1 / 4.7**、**日薪 ×1 / 1.5 / 2 / 2.5**，弓箭手射程每档 +10%（150 → 165 → 180 → 195）。

Upgrading costs `max(8, round((to.recruitCost − from.recruitCost) × 0.7))` gold per soldier. Climbing the ladder
rank by rank is always cheaper than buying the elite rank straight from a town, so militia are worth raising.
每名士兵的升级费用为 `max(8, round((目标兵种招募价 − 当前兵种招募价) × 0.7))` 金币。逐级升级总是比直接在城镇买精英便宜，所以民兵值得养。

The full ladder, per-rank statistics and per-rank upgrade prices are drawn as a **兵种升级图 · unit upgrade
diagram** in the in-game guide, generated straight from `src/game/units.js`.
完整的升级路线、各档属性与逐档升级价，都以 **兵种升级图** 的形式画在游戏介绍里，数据直接由 `src/game/units.js` 生成。

### 4.5 考试 · Exams

Only towns host exams, and only correct answers pay out — a wrong answer pays nothing.
只有城镇能参加考试，且只有答对才有钱——答错不发放任何奖励。

You pick a grade (三年级 / 四年级), one or more subjects, and a paper length of **5, 8 or 12** questions.
你可以选择年级（三年级 / 四年级）、一个或多个科目，以及 **5 / 8 / 12** 道题的题量。

An exam is scored `通过 / 结束` by `correct ≥ ceil(questions / 2)`, but the gold is paid per correct answer as
you go, so a failed paper still pays for what you got right.
考试以「答对 ≥ ceil(题数 / 2)」判定「通过 / 结束」，但金币是按答对逐题结算的，所以即使没通过，答对的题也照样给钱。

#### 难度 · Difficulty

The difficulty decides how much gold a correct answer pays. It is picked on the home screen before a new campaign
and can be changed at any time from the 🎚 chip on the world map; the setting belongs to the lord and is saved
with the campaign.
难度决定「答对一道题能拿多少金币」。开新局前在首页选择，游戏过程中也能随时用世界地图上的 🎚 芯片修改；难度属于领主本人，会随存档保存。

| 难度 Difficulty | 每题金币 Gold per correct answer | 说明 Note |
| --- | --- | --- |
| 🟢 简单 Easy | 三年级 20 / 四年级 26（原始数值） | 原来的数值。The original numbers. |
| 🟡 普通 Normal | 三年级 19 / 四年级 25 | 每题少 1 个金币。One gold less per question. |
| 🔴 困难 Hard | 三年级 18 / 四年级 24 | 每题少 2 个金币。Two gold less per question. |

The subject bonus (逻辑推理 +6、百科知识 +4) still applies on top, and a reward never drops below one gold.
科目加成（逻辑推理 +6、百科知识 +4）依然照常叠加，而且奖励最低为 1 个金币。

An old save without a difficulty is an easy game, so nothing changes for a campaign that started before the setting
existed.
旧存档没有难度字段时按「简单」处理，因此在难度设置出现之前开的局不会突然变难。

Subjects · 科目：英文 English · 语文 Chinese · 数学 Math · 逻辑推理 Logic · 百科知识 Encyclopedia.

The subject list is not hard-coded — it is whatever the mod registry currently holds, so a new question pack appears
in the exam setup as soon as it is registered. See 「题库扩展 · Question mods」 in section 13.
科目列表不是写死的：考试设置里显示的就是题库注册表当前持有的全部科目，因此新题库包一旦注册就会立刻出现在界面上。见第 13 节「题库扩展」。

#### 语文题型 · Chinese question types

The Chinese subject carries **reading comprehension** and a wide **ancient-poem** bank on top of the usual word
work. Each type is its own template, so the memory curve tracks them separately.
语文科目除了字词基础，还包含**阅读理解**与丰富的**古诗**题库；每种题型都是独立的模板，因此记忆曲线会分别记录。

| 题型 Type | 说明 What it asks |
| --- | --- |
| 📖 阅读理解 comprehension | 12 篇短文，每篇三题：主要内容、细节与词句体会。12 short passages, three questions each: the main idea, a detail and the meaning of a word. |
| 🏮 古诗接龙 poem | 下一句接上句，覆盖 30 首小学必背古诗。The next line of a line, over 30 poems children learn by heart. |
| 🖋️ 补全诗句 poemFill | 诗句里缺一个字，补上它。Fill in the missing character of a line. |
| 🏛️ 诗题 poemTitle | 由诗句猜诗题。Which poem do these lines come from? |
| 🧑‍🏫 作者 poemAuthor | 这首诗是谁写的。Who wrote this poem? |
| 🪶 上一句 poemPrev | 上一句是什么。Which line comes before this one? |
| 💭 诗意 poemMeaning | 这首诗表达了什么。What does the poem express? |

Every poem question carries an explanation, so a wrong answer teaches the title, the poet and the dynasty.
每道古诗题都带解析，答错时会告诉孩子诗题、作者与朝代。

#### 记忆曲线 · Memory curve

A paper is not a flat random draw. Every question carries a memory level from **0** (unfamiliar) to **5**
(mastered), and each candidate is weighted by that level before the draw.
出卷不是等概率随机抽取。每道题都带一个 **0**（生疏）到 **5**（熟练）的记忆等级，抽取前先按等级换算成权重。

| 记忆等级 Level | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 抽中权重 Weight | 1.00 | 0.55 | 0.30 | 0.17 | 0.09 | 0.05 |

- A correct answer raises the level by **1**; a wrong answer lowers it by **2**, so a question that slips becomes up
  to about four times as likely to come back.
  答对等级 **+1**，答错等级 **−2**，所以一时答错的题会立刻变得最多约四倍更容易再出现。
- **20 hours** without seeing a question costs one level, at most two levels per pass — the forgetting curve applied
  across sessions, not only inside one paper.
  一道题 **20 小时**没见到就掉一级，每次最多掉两级——这把遗忘曲线应用到了跨场次，而不只是单张试卷内。
- Weights never reach zero, so a mastered question still resurfaces for revision.
  权重永远不会归零，因此熟练题仍会偶尔出现用于复习。
- Declarative questions are tracked one by one (`<mod>:<itemId>`); generated templates are tracked per template
  (`<mod>#<kind>`), so a maths template cannot be memorised through its numbers.
  声明式题目逐题记录（`<mod>:<itemId>`），程序生成的题按模板记录（`<mod>#<kind>`），因此数学题不会靠记住数字就算「掌握」。
- The exam setup shows how many questions have been recorded and how many are mastered.
  考试设置页会显示已记录多少题、其中多少题已掌握。

### 4.6 战斗 · Battle

Battles open automatically when a hostile party reaches within **1.3 tiles** of the player.
当敌对部队进入到玩家 **1.3 格**范围内时自动进入战斗。

The arena is a **1000 × 680** field that is bigger than a phone screen, so the camera follows the fighting
instead of showing everything at once. Every troop group you bring — one family at one rank — is an
independent **squad** with its own order, formation and density, so you can send the spearmen forward, hold the
archers back and scatter the cavalry, all in the same fight.
战场是一片 **1000 × 680** 的场地，比手机屏幕还大，因此镜头会跟着战斗走，而不是把整块战场一次塞进屏幕。你带来的每个兵种档位（同一个家族 + 同一个档位）都是一支独立的**小队**，各自拥有命令、队形与密度，因此可以同时做到：长枪兵压上、弓箭手原地待命、骑兵散开包抄。

#### 战场地形 · Battlefield terrain

The field is not a flat lawn: it is divided into cells, and every cell carries a piece of terrain that changes how
a soldier fights there. The terrain is generated from the battle seed, so the same fight always looks the same.
战场不是一块平地：它被分成若干格子，每格有一种地形，会改变站在那里的士兵的战斗表现。地形由战斗种子生成，因此同一场战斗每次看到的地图都一样。

| 地形 Terrain | 效果 Effect |
| --- | --- |
| 🌳 森林 Forest | 树木掩体：防御 +15%，移动 −20%。Cover: defence +15%, movement −20%. |
| 🏜️ 沙地 Desert | 体力消耗：攻击 −10%，移动 −10%。The heat tires the troops: attack −10%, movement −10%. |
| 🌊 河流 River | 涉水而行：移动 −30%，防御 −5%。Wading is slow: movement −30%, defence −5%. |
| 💧 湖泊 Lake | 深水：无法通行，士兵会绕着走。Deep water: impassable, the soldiers walk around it. |
| ⛰️ 山地 Mountain | 居高临下：攻击 +10%，防御 −10%。The high ground: attack +10%, defence −10%. |

The ground under the fighters is read in `strike()`: the attacker's cell adds to its attack and the defender's
cell adds to its defence, so a fight that happens in a forest is a different fight from one on the plain.
攻击者脚下的格子会加攻击，防守者脚下的格子会加防御，因此森林里的一场和平原上的一场是两场不同的仗。

The lake is the only impassable ground. It never stands where an army deploys, and a soldier that gets stuck
behind one is nudged sideways, so a fight can never stall.
湖泊是唯一不可通行的地面。它不会出现在军队的出发位置上，而被湖泊挡住去路的士兵会被侧向推开，因此战斗永远不会卡住。

#### 战斗速度 · Battle speed

The ⚙ button in the corner of the battle screen opens the battle tools: the **speed** and the **terrain legend**.
The speed is **slow by default**, so a child can read the field and give orders before the next clash happens.
战斗界面角落的 ⚙ 按钮打开「战斗工具」面板：里面是**速度**与**地形说明**。速度**默认是慢速**，这样孩子来得及看清战场、赶在下一次交手前下达命令。

| 速度 Speed | 倍率 Multiplier | 说明 Note |
| --- | --- | --- |
| 🐢 慢速 Slow | ×0.6 | 默认。战斗慢半拍，方便看清每一个动作。The default: the fight crawls, so every move can be read. |
| 🚶 正常 Normal | ×1 | 游戏原本的速度。The speed the game always had. |
| 🐇 快速 Fast | ×1.8 | 战局推进很快，适合熟练之后。For a player who knows the ropes. |

#### 镜头 · Camera

The camera zooms with the armies: when they are far apart the whole field is seen from a distance, and when they
meet it zooms in. A finger drag pans the field and stops the auto-follow, and the 🎯 button brings the camera
back to the fighting.
镜头会随两军距离缩放：双方拉开时看全景，交手后自动拉近。用手指拖动战场可以自由查看，并会停止自动跟随；点 🎯 按钮让镜头重新回到战斗。

Tap a squad chip at the bottom (or 全军 for all of them), then give the order:
点底部的小队按钮选择部队（或选「全军」），然后下达命令：

| 命令 Order | 行为 Behaviour | 数值 Modifier |
| --- | --- | --- |
| ⚔️ 攻击 Attack | 全军压向最近的敌人，远程单位贴近时后撤风筝。Charge the nearest enemy; ranged squads back away while still shooting. | 攻击 ×1.08，防御 ×0.94 |
| 🛡️ 防守 Defend | 原地结阵，守住当前位置，远程单位站着对射。Hold the current spot and trade blows. | 攻击 ×0.96，防御 ×1.25 |
| 🏇 跟随 Follow | 贴身跟随指挥官移动，沿途交战。Escort the commander and engage whatever is close. | 攻击 ×1，防御 ×1.05 |
| 🎯 移动 Move | 整队走到点击处后原地待命。March to the tapped point and wait there. | 攻击 ×0.94，防御 ×1 |

Each squad also has a **formation** and a **density**, changed from the folded 「▦ 队形」 panel and applied
immediately. Formations decide how the soldiers of a squad are laid out; densities decide how tightly packed they are.
每支小队还有**队形**与**密度**，在收起的「▦ 队形」面板里切换，改动立即生效。队形决定这一小队怎么排，密度决定人和人之间的间隔。

| 队形 Formation | 效果 Effect |
| --- | --- |
| ▦ 方队 Square | 排成方块。Block. 防御 +6% |
| ▬ 一行 Single rank | 横排一线，正面最宽。Widest front. 攻击 +6% |
| ▤ 两行 Two ranks | 两排纵深。Two deep. 防御 +3% |
| ▥ 三行 Three ranks | 三排厚阵。Three deep. 防御 +8%，移动 −5% |
| ▲ 尖形 Wedge | 楔形突击。Shock wedge. 攻击 +12%，防御 −5% |
| ⁘ 随机 Scatter | 散兵散布，没有加成，但最难被围住。No bonuses, hardest to surround. |

| 密度 Density | 效果 Effect |
| --- | --- |
| ⋯ 松散 Loose | 间隔 38，远程受伤 −22%，防御 −6%，移动 +6% |
| ≡ 紧凑 Tight | 间隔 22，防御 +14%，移动 −8% |

Tapping the battlefield normally moves your commander marker; when the selected squad is on 移动, the same tap
plants its yellow rally flag instead.
点击战场通常是移动指挥官标记；当选中的小队处于「移动」时，同一次点击会改为插下它的黄色目标十字。

Damage is `max(1, round(atk × 攻击加成 × 克制系数 × 脚下地形攻击 × 目标防御 × 脚下地形防御 × 0.5 + 随机值))`; melee units swing every 1.0 s and
ranged units fire a projectile every 1.6 s. Melee units engage inside 26 px; archers shoot at 150 px and every rank
beyond 初级 adds 10%.
伤害为 `max(1, round(攻击 × 攻击加成 × 克制系数 × 脚下地形攻击 × 目标防御 × 脚下地形防御 × 0.5 + 随机值))`；近战单位每 1.0 秒攻击一次，远程单位每 1.6 秒射出一支箭。近战单位在 26 px 内接战；弓箭手射程 150 px，每升一档 +10%。

The three families form a rock-paper-scissors cycle — **长枪兵克制骑兵、骑兵克制弓箭手、弓箭手克制长枪兵** —
worth **+40% attack when countering and −25% when countered**.
三个主力兵种形成循环克制 —— **长枪兵克制骑兵、骑兵克制弓箭手、弓箭手克制长枪兵** —— **克制方攻击 +40%，被克制方 −25%**。

**After the battle, your warband is exactly the soldiers who survived it.**
**战斗结束后，你的队伍就是战场上真正的幸存者。**

If every soldier falls, the warband is empty; there is no free replacement troop.
如果全军覆没，队伍就真的是空的，不会凭空补兵。

### 4.7 物资 · Supplies

Each battle consumes **3 food**; fighting with an empty larder weakens the army's attack by 25%.
每场战斗消耗 **3 份军粮**；粮草不足时全军攻击力下降 25%。

Each horse in the baggage train adds **+1% attack** to the whole army, capped at **+10%**.
每匹随军战马为全军提供 **+1% 攻击**，最多 **+10%**。

### 4.8 角色信息面板 · Lord info panel

The world map top bar carries a tappable **👤 角色详情** chip that opens a read-only popup summarising the
current character: troops, treasury and supplies in one place.
世界地图顶部状态栏有一个可点击的 **👤 角色详情** 芯片，打开后会弹出只读的角色面板，把兵力、资金和物资集中展示。

| 区块 Block | 内容 Contents |
| --- | --- |
| 头部 Header | 领主名字、第几天、所在地形与时钟状态（停滞 / 流逝 / 扎营）。Lord name, day counter, the terrain you are standing on and the clock state (frozen / flowing / camping). |
| 资金与物资 Treasury and supplies | 金币、军粮、战马，并附消耗说明。Gold, food, horses and what they do. |
| 部队 Warband | 每个兵种一行：等级 T、数量、攻 / 防 / 血、该兵种日薪小计；末行汇总每日军饷支出。One row per unit type: tier, count, atk/def/hp and its daily wage subtotal, plus a total wage row. |
| 战绩 Record | 战斗胜 / 总、胜率、参加考试次数、累计答对题数。Wins / battles, win rate, exams taken and total correct answers. |

The panel reads from the player store and the world store, so it always matches what the battle and exam screens
see; it is purely informational and never changes state.
面板数据直接读自 player store 和 world store，因此与战斗、考试界面看到的数据始终一致；它只展示信息，不会改变任何状态。

### 4.9 存档 · Saving

Progress is written to `localStorage` automatically (every 6 s on the world map) and on every settlement action.
进度会自动写入 `localStorage`（在世界地图上每 6 秒一次），并在每次据点操作后保存。

Each player name gets its own save slot, so several people can share one browser.
每个玩家名字有独立的存档位，因此多个人可以共用同一个浏览器。

### 4.10 受伤与恢复 · Wounds and recovery

A soldier does not simply vanish when it goes down. In a fight a soldier that reaches **0 HP** is defeated: it
either **dies for good** or — with a little luck, and a lot more luck with a hospital — it survives as a
**wounded soldier** at 1 HP.
士兵不会在倒下时凭空消失。战斗中生命值归零的士兵算「被打败」：要么**彻底阵亡**，要么——靠一点运气，医院会大幅提高概率——以 1 点生命的**伤兵**活下来。

A soldier group is stored as `{ type, tier, count, hp }`, and `hp` holds one value per soldier, so the warband
remembers who is hurt. A wounded soldier enters the next battle with the health it still has.
士兵组以 `{ type, tier, count, hp }` 存储，`hp` 与士兵一一对应，队伍因此记得谁受了伤；伤兵带着剩余生命进入下一场战斗。

| 情况 Situation | 每点恢复 Healing per day | 说明 Notes |
| --- | --- | --- |
| 行军 / 扎营 Marching or camping | **6** | 慢，但一直在恢复。Slow, but never stops. |
| 在据点休整 Resting in a settlement | **24** | 在城镇里恢复快得多。Much faster inside a town. |
| 自己的城镇 Own town | **24 + 6 × (等级 − 1)** | 自己的城镇恢复最快，等级越高越快。Fastest in your own town, and the level counts. |
| 医院加成 Hospital | **×(1 + 0.5 × 等级)** | 每一级医院把恢复速度再乘一次。Every hospital level multiplies the rate again. |

The **战果 · battle result** screen reports the three numbers that matter: 阵亡 (dead), 受伤 (wounded) and 救回
(saved by the hospital). The **👤 角色详情** panel shows how many soldiers are hurt and the average health of
the warband.
战果界面会报告三个关键数字：阵亡、受伤与救回；**👤 角色详情** 面板会显示队伍里有多少伤兵与平均体力。

A soldier that is promoted to a higher rank comes back **at full health**: new gear, new soldier.
升档后的士兵会以**满血**归队：换了装备，就是新兵。

### 4.11 据点归属、驻军与围城 · Ownership, garrisons and sieges

Every settlement belongs to exactly one holder, and the holder decides what the lord may do with it.
每个据点都只有一个归属，归属决定主角能对它做什么。

| 归属 Owner | 城镇 Town | 村庄 Village | 说明 Notes |
| --- | --- | --- | --- |
| 无主 Neutral | 可进入，可**占领** | 可进入 | 谁都可以进；无主的城镇如果没人防守，插旗就能拿下，有人守军就要先打下来。Open to everybody; an unclaimed town nobody defends is taken by raising the flag, one that holds soldiers has to be stormed. |
| 苍狼 / 赤鹰 A kingdom | 可进入，也可**攻打** | 可进入 | 可以先进去考试与招募，也可以打下来据为己有。You may walk in and trade, or take it by force. |
| 强盗 Bandits | **永远不占城镇** | 不可进入，可攻打 | 强盗只能控制村庄。Bandits never hold a town. |
| 你的 Your own | 可进入 | 可进入 | 自己的城镇没有占领与围城按钮，只有「进入」。Your own town has no claim and no siege button — just the door. |

- The map draws an **ownership ring** in the colour of the holder around every settlement, and the troop badge
  in the corner shows the **garrison** that defends it.
  地图上每个据点都有一圈**归属光环**，颜色就是归属方的颜色；右上角的兵力角标是它的**驻军**。
- An **unclaimed town** belongs to nobody. When it holds **no soldiers** the bottom bar offers **🚩 占领** and
  the lord simply raises his flag; the town becomes his without a fight and starts over as a poor hamlet.
  When it still **holds a garrison** the button becomes **⚔️ 攻城** with the number of defenders — the flag has
  to be planted the hard way, so the garrison has to be beaten first. Winning hands the town over; losing leaves
  it to its defenders, and the lord may try again.
  **无主的城镇**谁都可以进。**没有守军**时底部是 **🚩 占领**，插旗就能拿下，城镇从零开始发展；**还有守军**时按钮变成
  **⚔️ 攻城**（并显示守军人数），必须先把守军打下来才能占领。打赢了城镇归你，打输了城镇仍归原样，可以再来一次。
- A **bandit village** cannot be entered. The bottom bar offers **⚔️ 赶走强盗** instead, which starts a fight
  against the bandits in the village. Win and the village becomes unclaimed and can be entered.
  **强盗村庄**进不去，底部按钮变成 **⚔️ 赶走强盗**，直接与村中的强盗士兵开战；打下来之后村庄变成无主，可以进入。
- A **kingdom town** can be entered without conquering it — the lord may examine and recruit there — and the
  bottom bar also offers **🏰 准备围城**: the siege needs **2 天** of preparation, and **the clock keeps
  running while you prepare** — the town uses the time too.
  **王国城镇**可以直接进去（考试、招募都行），也可以打下来：底部还有 **🏰 准备围城**，围城需要 **2 天**准备，
  而且**准备期间时间照常流逝**——城镇也会利用这段时间。
- While the siege is prepared the garrison **keeps growing** (up to four extra soldiers) and the owner
  **sends a relief warband** that marches to the town and turns on the attacker on the way.
  准备期间驻军会**继续增加**（最多多出四名），归属方还会**派出援军**奔向城镇，并在路上反击进攻者。
- When the preparation is over the button becomes **⚔️ 攻打**. The garrison fights for the town, and if the lord
  wins the town is **his**: no garrison, level 1, and a fresh start.
  准备结束后按钮变成 **⚔️ 攻打**，驻军为城镇而战；主角打下来，城镇就归他所有：驻军清空、等级回到 1、重新开始。
- A siege can always be **called off**: while it is prepared the bottom bar shows the countdown and a
  **🚫 取消围城** button, and the same button is there once the preparation is over. Calling it off stops the
  clock as well, so the world freezes again.
  围城随时可以**中断**：准备期间底部会显示倒计时和 **🚫 取消围城** 按钮，准备结束后同样有这个按钮；中断后时钟也会停下，世界重新冻结。
- A **failed assault breaks the siege**: the lord has to gather his troops and **prepare the siege again**
  before he may attack a second time.
  **攻打失败会中断围城**：主角必须重新集结部队、**重新准备围城**，才能再次发起进攻。

### 4.12 城镇发展与设施 · Town development and facilities

A captured town is a project. It develops through exams, and its level decides how good it gets.
夺下来的城镇是一项长期工程：靠考试发展，等级决定它能有多好。

```
考试 exam ──▶ 主角的钱袋 lord's purse ──▶ 注入资金 inject ──▶ 城镇金库 town funds ──▶ 设施 facilities
   │                                                                        │
   └──▶ 发展 development ──▶ 繁荣度 prosperity ──▶ 等级 level ◀────────────┘
```

- **考试 → 资金与发展.** The exam always pays the **lord personally** — even in a town he owns, so he is never
  short of money. In a town he owns, every correct answer additionally adds **+2 开发** to that town.
  **考试 → 资金与发展。** 考试收入**永远进主角的钱袋**——即使在自己的城镇里也不会缺钱；
  而在自己城镇里，每答对一题还会额外给城镇 **+2 开发**。
- **注入资金 · Inject funds.** The 「🏛️ 城镇」 panel has an **注入资金** button: it moves **100** gold from the
  lord's purse into the town treasury, which is where the money for the facilities comes from.
  **注入资金。** 「🏛️ 城镇」页签里的「注入资金」按钮会从主角钱袋里拿出 **100** 金币放进城镇金库，
  建造设施用的就是这笔钱。
- **发展 → 繁荣度.** Every day a town gains or loses prosperity: above **40** development it climbs
  (`(发展 − 40) × 0.15` per day), below 40 it slides back. A town also earns **繁荣度 × 0.15** gold a day.
  **发展 → 繁荣度。** 每天城镇的繁荣度随发展变化：高于 **40** 时按 `(发展 − 40) × 0.15` 上涨，低于 40 时下滑；
  城镇每天还有 `繁荣度 × 0.15` 的收入。
- **投入发展.** Surplus town money can also be turned into development: **60 城镇资金 → +6 开发**.
  **投入发展。** 城镇里多余的钱也可以换成发展：**60 城镇资金 → +6 开发**。
- **繁荣度 → 等级.** Prosperity reaching the next threshold promotes the town: **40 → Lv.2 小镇**,
  **70 → Lv.3 城镇**, **90 → Lv.4 大城**. The level is shown in the **top left corner of the town screen** and
  on the map name plate.
  **繁荣度 → 等级。** 繁荣度达到阈值就升级：**40 → 二级 小镇**、**70 → 三级 城镇**、**90 → 四级 大城**；
  等级显示在**城镇界面左上角**，地图上的名字牌也会带 `Lv.N`。
- A higher level means **better recruits** (the weight of the higher ranks rises with every level), **faster
  recovery in your own town** and a **larger garrison**.
  等级越高，**兵源越好**（高阶权重随等级上升）、**自己的城镇恢复更快**、**驻军也更多**。

Two facilities can be built with the town's money, and both can be upgraded three times.
两种设施可以用城镇资金建造，都能升到三级。

| 设施 Facility | 造价 Cost | 效果 Effect |
| --- | --- | --- |
| 🏥 医院 Hospital | 120 / 210 / 300 | 恢复速度 ×(1 + 0.5 × 等级)，战败存活率 +10% / 级。Recovery ×(1 + 0.5 × level) and +10% survival per level. |
| 🏚️ 军营 Barracks | 150 / 250 / 350 | 全军攻击与防御 +6% / 级。+6% attack and defence for the whole army per level. |

Resting inside a settlement also keeps the town developing: the clock runs, the wounded heal and the town gains
prosperity — while the warbands on the map hold their ground.
在据点里休整时城镇照常发展：时间流逝、伤兵恢复、城镇繁荣度照涨，而地图上的敌军原地不动。

### 4.13 势力会变强 · The factions grow

The world does not stay as it was found. Every day the factions reinforce their warbands, and new bands of
bandits wander onto the map.
世界不会一直停在最初的样子：每天各势力都在补充兵员，新的强盗也会随机出现在地图上。

- **强盗上限 50 支.** A new bandit warband appears every second day until the map holds **50** of them; the
  rest keep roaming and keep growing.
  **强盗上限 50 支。** 每隔一天出现一伙新的强盗，直到地图上有 **50** 支为止；它们会继续游荡、继续变强。
- **势力的兵力上限跟着你的繁荣度走.** The total number of soldiers a faction may field is
  `20 + 0.6 × (所有已占领城镇的繁荣度之和)`. A rich empire makes the rivals stronger — that is the point of
  taking towns.
  **势力的兵力上限跟着你的繁荣度走。** 每个势力在地图上的兵力上限是
  `20 + 0.6 ×（所有已占领城镇的繁荣度之和）`。你的领地越富，敌人越强 —— 这正是打城镇的意义。
- **每天补一名士兵.** A faction below its cap reinforces its strongest warband by one soldier a day, and
  sometimes a rank-2 veteran instead of a raw recruit.
  **每天补一名士兵。** 势力没到上限时，每天给它最强的一支部队补一名士兵，偶尔补的是二级老兵而不是新兵。

### 4.14 版本号与更新内容 · Version and changelog

The version of the build lives in `src/game/versions/`: `index.js` exports `VERSION` and `CHANGELOG`, one file per
release (`v0.0.1.js`, …) holds the batches that release shipped, and `batches.js` is generated from `progress.md`.
版本号集中在 `src/game/versions/`：`index.js` 导出 `VERSION` 与 `CHANGELOG`，每个发布版本一个文件（`v0.0.1.js` …）写着这次发布包含的批次，而 `batches.js` 是从 `progress.md` 生成的。

- **The number is `major.minor.patch`, and only the patch moves.** The game is still in its early stage, so every
  release bumps the last digit only: `v0.0.1` → `v0.0.2` → `v0.0.3`; the major and minor numbers stay at zero.
  **版本号是 `主版本.次版本.修订号`，目前只更新修订号。** 游戏还处于早期阶段，每次发布只加最后一位：
  `v0.0.1` → `v0.0.2` → `v0.0.3`，主版本与次版本一直是 0。
- **The home screen shows it.** The title carries a `版本 v0.0.1` badge, and the badge at the bottom of the page opens
  a dialog with the update notes of the current release: a short summary and every batch it shipped.
  **首页会显示它。** 标题下面有「版本 v0.0.1」徽章，页面底部的徽章点开是一个对话框，写着本次发布的更新内容：
  一段摘要加上这次发布包含的每个批次。
- **The notes come from `progress.md`.** `node tools/build-versions.mjs` parses the 「已完成功能」 section of the
  progress file and writes it into `src/game/versions/batches.js`, so the progress file stays the one source of truth.
  **更新内容来自 `progress.md`。** `node tools/build-versions.mjs` 解析进度文件的「已完成功能」一节，写进
  `src/game/versions/batches.js`，因此进度文件是唯一的事实来源。
- **Only game features reach the dialog.** Every bullet of that section starts with either `▶` (a change a player
  can see or feel) or `🔧` (an internal note). The generator keeps the `▶` bullets and drops the `🔧` ones, so the
  dialog never shows file names, scripts or test counts — and a batch with nothing player-facing (a batch of pure
  documentation, say) does not appear at all.
  **对话框里只有游戏功能。** 「已完成功能」一节的每条内容都以 `▶`（玩家看得见的变化）或 `🔧`（开发层面的改动）开头；
  生成脚本只保留 `▶`，因此对话框里不会出现文件名、脚本名或检查项数量 —— 一条功能都没有的批次（比如纯文档批次）干脆不显示。
- **Helpers.** `versionLabel('0.0.1')` renders `v0.0.1`, `nextPatchVersion('0.0.1')` gives `0.0.2` and
  `changelogOf(version)` filters the notes of one version.
  **辅助函数。** `versionLabel('0.0.1')` 输出 `v0.0.1`，`nextPatchVersion('0.0.1')` 得到 `0.0.2`，
  `changelogOf(version)` 取出某一个版本的更新内容。

### 4.15 练兵 · Training

While the camp is pitched, the world map offers a **🎯 练兵** button that opens the battle field as a drill ground.
扎营时，世界地图上会出现「🎯 练兵」按钮，点它就把战场变成一块训练场。

- **No enemy at all.** The field holds the lord's own soldiers and eight **wooden dummies** standing on the far
  side; the dummies never fight back, they only take blows.
  **完全没有敌人。** 场上只有主角自己的士兵和对面的八个**训练木桩**，木桩只挨打，绝不还手。
- **Nothing can be lost.** A training session has no outcome at all: it does not end, no soldier can die, and the
  warband, the purse, the food store and the record are left exactly as they were.
  **练兵不会损失任何东西。** 训练场没有胜负，不会结束，士兵不会阵亡，队伍、金币、军粮与战绩都原样不动。
- **The dummies stand back up.** A dummy that is knocked down is on its feet again two seconds later, so a drill
  never runs out of targets.
  **木桩会自己立起来。** 木桩被打倒后两秒重新立起，训练永远有靶子。
- **Everything still works.** The whole command bar is live: pick a squad, give it an order (攻击 / 防守 / 跟随 / 移动),
  change its formation and density, drag the camera and plant rally flags.
  **照常操练。** 命令栏一切照旧：选小队、下命令（攻击 / 防守 / 跟随 / 移动）、换队形与密度、拖动镜头、插下目标十字。
- **Leaving is one tap.** The 🏕 结束练兵 button at the bottom of the command bar returns to the world map, and the
  camp is still pitched.
  **一键退出。** 命令栏上的「🏕 结束练兵」回到世界地图，营地还保持着。

### 4.16 快速战斗 · Quick battle

The home screen carries a **⚡ 快速战斗** entry: it opens a simulator that answers "who would win?" without a
campaign. Pick the battlefield, the two sides and the size of the armies, and the simulation fights the fight many
times over and counts the results.
首页有一个「⚡ 快速战斗」入口：它打开一个模拟器，不用打战役就能回答「谁打得过谁」。选好战场、敌我势力与兵力规模，
模拟器会一遍遍地把这场仗打完并统计结果。

- **The battlefield can be picked.** `ARENA_MAPS` in `src/game/arena.js` holds six presets — 混战 (mixed), 平原
  (plain), 密林 (forest), 山地 (mountain), 大河 (river) and 湖泽 (lake) — and `generateArenaTerrain()` lays the
  ground out after the preset. The same presets work in a real battle: `createBattle()` takes an `arenaMap`.
  **战场可以选。** `src/game/arena.js` 的 `ARENA_MAPS` 有六种预设 —— 混战 / 平原 / 密林 / 山地 / 大河 / 湖泽 ——
  `generateArenaTerrain()` 按预设摆地形；真实战斗也用同一套预设（`createBattle()` 有 `arenaMap` 参数）。
- **Both sides can be picked.** The lord fields one of four armies (民兵 / 长枪兵 / 弓箭手 / 骑兵, at the middle
  rank) and the enemy is one of the three factions (强盗 / 苍狼王国 / 赤鹰王国), each with its own mix of
  families.
  **敌我势力可以选。** 己方四选一（民兵 / 长枪兵 / 弓箭手 / 骑兵，中级档），敌方三选一（强盗 / 苍狼王国 / 赤鹰王国），
  每个势力有自己的兵种配比。
- **The size of the armies can be picked.** 小队 8×8 / 中队 16×16 / 大队 32×32 / 大军 64×64, and 5, 20 or 50 fights.
  **士兵规模可以选。** 小队 8×8 / 中队 16×16 / 大队 32×32 / 大军 64×64，可以跑 5 / 20 / 50 场。
- **It is the real battle.** `src/game/quickBattle.js` reuses `createBattle()` and `stepBattle()` from
  `src/game/battle.js` — only the step is as large as it can be, because nobody watches it — so the numbers come
  from the same fight the campaign fights.
  **这就是真战斗。** `src/game/quickBattle.js` 复用 `src/game/battle.js` 的 `createBattle()` 与 `stepBattle()`，
  只是把步长开到最大（没人观看），因此数字与战役里那场仗同源。
- **The report.** The win rate, the wins, losses and draws, the average survivors and fallen on both sides, the
  average length of a fight and the detail of every round.
  **结果一览。** 胜率、胜 / 负 / 平场次、双方平均剩余与阵亡、平均时长，以及每一场的明细。

## 7. 游戏操作 · Controls

- **查看时间 See the time** — 世界地图顶部的 📅 芯片显示第几天、几点几分（一天 24 秒，1 秒 = 游戏里的 1 小时）和当天的进度条；据点界面与角色信息面板里也有同样的时钟。The 📅 chip in the world-map status bar shows the day, the hour of that day (a day is 24 seconds, one second is one in-game hour) and a bar for the day's progress; the settlement screen and the lord panel carry the same clock.
- **昼夜 Day and night** — 每天的最后五分之一（19:12 起）是夜晚：地图变暗、主角与所有部队都变慢 25%，主角身边有一圈灯光。The last fifth of every day (from 19:12) is night: the map darkens, the lord and every warband slow down by 25%, and the lord keeps a lantern light around him.
- **移动 Move** — 点击世界地图任意位置；游戏时间只在移动时流逝。Tap anywhere on the world map; game time advances only while the lord walks.
- **扎营 Camp** — 点底部「⛺ 扎营」原地扎营，时间与敌军照常流转；点「🔥 拔营」或点地图移动即结束。Tap 「⛺ 扎营」 to rest in place while time keeps running; 「🔥 拔营」 or a map tap breaks camp.
- **练兵 Drill** — 扎营时底部多出「🎯 练兵」按钮，点它进入训练场：场上只有自己的士兵和训练木桩，没有敌人，不会死人，练习完点「🏕 结束练兵」回到世界地图。While the camp is pitched the bottom bar grows a 「🎯 练兵」 button: it opens a drill ground with the lord's own soldiers and wooden dummies, no enemy and no losses, and 「🏕 结束练兵」 takes you back to the world map.
- **快速战斗 Quick battle** — 首页的「⚡ 快速战斗」进入模拟器：选战场、选敌我势力、选士兵规模，点「⚡ 开始模拟」跑出胜率。The 「⚡ 快速战斗」 entry on the home screen opens the simulator: pick a battlefield, the two sides and the size of the armies, then 「⚡ 开始模拟」 reports the win rate.

## 10. 游戏数据 · Game Data

All state lives in `localStorage`; there is no server.
所有状态都存在 `localStorage` 里，没有后端。

| 键 Key | 内容 Contents |
| --- | --- |
| `kids-war-game:users` | 玩过的领主名字列表。The list of player names used on this browser. |
| `kids-war-game:save:<name>` | 单个存档：世界种子、地形（压缩为地形 id 数组）、据点、部队、玩家坐标、天数、金币、兵员、物资、统计。One save slot: world seed, terrain (stored as a compact terrain-id array), settlements, parties, player position, day, gold, troops, supplies and stats. |

Saved fields · 存档字段：`seed` `gridIds` `settlements` `parties` `playerPos` `day` `gold` `troops` `supplies` `stats` `questionStats` `difficulty`.

`difficulty` carries the difficulty of the campaign; a save without it is an easy game.
`difficulty` 保存本局的难度；没有这个字段的旧存档按「简单」处理。

`day` carries the campaign clock across a reload; the in-flight clock accumulator and the camp flag are not
saved, so a resumed game always starts standing still with the clock frozen.
`day` 让战役天数跨刷新保留；尚未走完的时钟进度与扎营标记不写入存档，因此读档后总是原地站立、时钟冻结。

A warband entry is `{ type, tier, count, hp }` (family, 1–4 rank, soldiers and one hit-point value per soldier).
Loading rewrites the pre-standard keys (`infantry` / `veteran` / `marksman` / `knight`) through `normalizeTroops()`,
so an old save keeps its strength, and a save that predates the wounds starts every soldier at full health.
队伍每一项是 `{ type, tier, count, hp }`（家族、1–4 档位、人数，以及每人当前生命值）。
读档时会用 `normalizeTroops()` 改写旧版 key（`infantry` / `veteran` / `marksman` / `knight`），因此旧存档的兵力不会丢；
早于「受伤」系统的存档则让每名士兵以满血归队。

A settlement carries `owner` (`neutral` / `player` / `bandit` / `wolf` / `eagle`), `level`, `prosperity`,
`development`, `funds`, `facilities` (`hospital` / `barracks`), `garrison` and `siege`. A save that predates the
ownership system gets a deterministic owner per settlement, so the world still has hostile towns to take.
每个据点保存 `owner`（`neutral` / `player` / `bandit` / `wolf` / `eagle`）、`level`、`prosperity`、`development`、
`funds`、`facilities`（`hospital` / `barracks`）、`garrison` 与 `siege`；早于归属系统的存档会按据点 id 稳定地
补一个归属，因此世界里仍有可以攻打的城市。

`stats` 记录 `days` `battles` `wins` `exams` `correct`。
`stats` tracks `days` `battles` `wins` `exams` `correct`.

`questionStats` holds the memory curve, keyed per question — `{ "<mod>:<itemId>" | "<mod>#<kind>": { level, right, wrong, lastSeen } }` — pruned to the 1200 most recently seen records on save; a save without the field simply starts with an empty curve.
`questionStats` 保存记忆曲线，按题目为键 —— `{ "<mod>:<itemId>" | "<mod>#<kind>": { level, right, wrong, lastSeen } }` —— 存档时只保留最近见到的 1200 条记录；旧存档没有该字段时按「全部生疏」处理。

Deleting a save is as simple as removing those keys, or calling `deleteGame(name)` from `src/game/save.js`.
删除存档只需移除这些键，或调用 `src/game/save.js` 里的 `deleteGame(name)`。

## 11. 手机端支持 · Mobile Support

The game is designed for phones first: the layout uses a `max-width: 560px` breakpoint that stacks the world
HUD, collapses the legend, shrinks the minimap, wraps list rows and turns exam answers into a single column.
游戏以手机优先设计：`max-width: 560px` 断点会把世界地图 HUD 改为竖排、默认收起图例、缩小小地图、把列表行折行、并把考试选项改成单列。

Touch targets are at least 40–44 px, the world map uses a `click` handler (works for taps, mice and automation),
and rubber-band scrolling plus the grey tap highlight are disabled.
触控目标最小 40–44 px；世界地图使用 `click` 事件（触摸、鼠标、自动化都能触发）；橡皮筋滚动与点击灰块已关闭。

The app fills the dynamic viewport (`100dvh`) so the mobile URL bar does not clip the bottom buttons, and the HUD
respects `env(safe-area-inset-*)` on notched devices.
应用使用动态视口高度（`100dvh`），因此手机地址栏不会裁掉底部按钮；HUD 也通过 `env(safe-area-inset-*)` 适配刘海屏。

The canvas caps device pixel ratio at 2 and caches its vignette gradient per resize, keeping the redraw cheap.
画布的 device pixel ratio 上限为 2，并且暗角渐变只在尺寸变化时生成一次，让每帧重绘足够轻量。

The detailed atlas is panned with **pointer events** and `touch-action: none`, so a finger drag scrolls the map
instead of the page, and `setPointerCapture` keeps the drag alive when the finger leaves the canvas.
详细地图用 **pointer 事件**加 `touch-action: none` 拖动，因此手指拖动的是地图而不是页面；`setPointerCapture` 保证手指移出画布后拖动仍然连续。

The **battle field** is designed the same way: it is bigger than a phone screen, so the camera follows the fighting
and a finger drag pans the field (the battle canvas uses the same pointer-event scheme, and a drag never plants a
rally flag). The battle tools sit in the top-right corner instead of the command bar, so the field stays as tall as
possible on a phone.
**战场**也是同样的思路：它比手机屏幕大，因此镜头跟着战斗走，手指拖动可以平移战场（战斗 canvas 用同一套 pointer
事件，拖动时不会误插旗）。战斗工具放在右上角而不是底部命令栏，这样手机上的战场能留到最大。

The battle runs **slow by default**, so a child can read the field and give orders before the next clash — the fast
speed is one tap away in the ⚙ panel.
战斗**默认慢速**，孩子来得及看清战场、赶在下一次交手前下令；想加速，点 ⚙ 面板即可。

## 13. 游戏维护 · Maintenance

### 新增兵种 · Add a unit

Add a family to `UNIT_TYPES` in `src/game/units.js` with its base (rank-1) statistics, `recruitCost`, `wage` and
the family it counters; ranks, prices and battle stats are all derived from the shared `TIER_RANKS` multipliers, so
you never write a per-rank table. To make it recruitable, add its 初级 row to `TOWN_POOL` in `src/game/recruit.js`
and, if it is a militia-style branch, list it in `BRANCHES`.
在 `src/game/units.js` 的 `UNIT_TYPES` 里加一个家族，写好一级（基础）属性、`recruitCost`、`wage` 和它克制的家族；档位、价格与战斗数值全部由共用的 `TIER_RANKS` 乘数推导，不需要写逐档表格。要让它能被招募，就把它的初级档加进 `src/game/recruit.js` 的 `TOWN_POOL`；如果它是像民兵那样的一级分支，还要加进 `BRANCHES`。

`upgradesFor()` builds the promotion edges and `upgradeCost()` prices them from the two recruit prices, so the
upgrade tree and the guide's diagram follow automatically.
`upgradesFor()` 负责生成升级连线，`upgradeCost()` 用两端招募价算出价格，因此升级树和介绍里的升级图都会自动跟着变。

Every definition returned by `unitDef()` carries both `key` and `type`, and the edges reuse those very objects, so
an edge can be handed straight to `player.upgradeTroops()` — `{ type, tier }` is the shape the whole game stores
soldiers in, and it is also what the panel's `v-for` keys and steppers are built from.
`unitDef()` 返回的定义同时带 `key` 与 `type`，算升级边时直接复用这批对象，因此一条边可以原样交给 `player.upgradeTroops()`——全游戏存兵都用 `{ type, tier }` 这个形状，界面的 `v-for` key 与数量步进器也由它构成。

It also needs a sprite named after the family under `public/pixel/unit/` (use `TYPE_SPRITES` in `units.js` to map
ranks 1–2 and 3–4 to different art) and an entry in `SPRITE_CATEGORY`, see 「美术素材」below.
它还需要一张以家族 key 命名的 `public/pixel/unit/` 素材（用 `units.js` 里的 `TYPE_SPRITES` 把 1–2 档和 3–4 档映射到不同素材），并在 `SPRITE_CATEGORY` 里登记，见下文的「美术素材」。

Old saves that still hold pre-standard keys (`infantry`, `veteran`, `marksman`, `knight`) are rewritten by
`normalizeTroops()` in `units.js`; add an entry to `LEGACY_TYPES` there whenever a family is renamed.
仍保存着旧 key（`infantry`、`veteran`、`marksman`、`knight`）的旧存档由 `units.js` 里的 `normalizeTroops()` 改写；以后若再改名，记得往那里的 `LEGACY_TYPES` 补一条。

### 美术素材 · Pixel art assets

Every sprite is a 32x32 PNG under `public/pixel/<category>/`, generated by `tools/pixel-assets/generate.mjs`,
which draws through the Pixelorama bridge registered as the `pixelorama` server in the repository root `.mcp.json`
(Pixelorama must be open and listening on `127.0.0.1:7373`).
所有素材都是 `public/pixel/<分类>/` 下的 32×32 PNG，由 `tools/pixel-assets/generate.mjs` 生成；该脚本通过仓库根目录 `.mcp.json` 里注册的 Pixelorama 桥接作画（需要 Pixelorama 处于打开状态并监听 `127.0.0.1:7373`）。

```bash
node tools/pixel-assets/generate.mjs                    # 全部素材 every asset
node tools/pixel-assets/generate.mjs unit commander     # 只画某些分类 only these categories
node tools/pixel-assets/generate.mjs militia            # 只画一张 a single sprite
```

| 分类 Category | 素材 Sprites |
| --- | --- |
| `unit/` | 四个家族各两档外观加领主：militia、spearman / spearman-elite、archer / marksman、cavalry / knight、lord |
| `settlement/` | town, village |
| `commander/` | 三个势力的地图将领：bandit（灰色蒙面）、wolf（紫袍狼纹盾）、eagle（骑马披风骑士） |
| `terrain/` | 地形装饰与地图标记：forest, mountain, water, desert, camp（扎营的帐篷与篝火） |

Faction commander art takes its cloth colour from `src/game/factions.js`, which the generator imports directly, so
the sprite, the legend swatch and the minimap dot are all one value.
势力将领素材的衣色取自 `src/game/factions.js`（生成脚本直接 import 该文件），因此素材、图例色块与小地图圆点是同一个值。

Unit art is **two looks per family plus rank pips**: ranks 1–2 use the basic sprite, ranks 3–4 the elite one, and
the arena draws 1–4 small pips over each soldier so the exact rank stays readable — `unitSprite(type, tier)` in
`src/game/units.js` is the one place that decides this.
兵种素材是**每家族两档外观 + 档位血点**：1–2 档用普通外观，3–4 档用精英外观，战场上再在每个士兵头顶画 1–4 个小点，保证档位一眼可辨——判断规则集中在 `src/game/units.js` 的 `unitSprite(type, tier)`。

Art is authored on a 32x32 design grid and exported at `scale: 1`, so the file matches the drawn pixels one to one.
素材在 32×32 的设计网格上绘制，并以 `scale: 1` 导出，因此文件与画出的像素一一对应。

The game only ever draws them at integer scales — nearest-neighbour on canvas, `image-rendering: pixelated` in the
DOM — because a fractional scale is what makes pixel art look blurry. `src/game/pixelAssets.js` is the single place
that maps a unit type, settlement kind, faction or terrain key to its file.
游戏只用整数倍缩放绘制 —— canvas 关闭插值，DOM 用 `image-rendering: pixelated` —— 因为小数缩放正是像素画发糊的原因。单位类型、据点类型、势力与地形键到文件的对应关系集中在 `src/game/pixelAssets.js`。

Adding a sprite: add a painter to `buildAssets()` in `generate.mjs`, give it a name, register that name in
`SPRITE_CATEGORY`, then re-run the generator. Keep it one pixel clear of the canvas edge, otherwise the outline
pass clips the silhouette.
新增素材：在 `generate.mjs` 的 `buildAssets()` 里加一个绘制函数并起名，把名字登记到 `SPRITE_CATEGORY`，然后重新运行脚本。素材要与画布边缘留出 1 像素，否则描边会被裁掉。

The generator owns the silhouette outline, the shared body plan of the units and the palette, so a change to one
pawn reads across the whole roster; `UNIT_ART` in `generate.mjs` is the table that gives each sprite its cloth,
helmet and weapon, and `COMMANDERS` does the same for the three map commanders, which layer on that same body plan
(hood + mask, cape + wolf-marked shield, mounted lancer).
生成脚本统一负责描边、各单位共用的身体结构与配色，因此改一处就能让整套兵种保持一致；`generate.mjs` 里的 `UNIT_ART` 就是给每张素材指定衣色、头盔与武器的表，`COMMANDERS` 则用同一套身体结构规定三位地图将领（连帽蒙面、披风加狼纹盾、骑马枪骑）。

### 新增地形 · Add terrain

Add the type to `TERRAIN` in `src/game/terrain.js`, give it a base colour in `drawTile()` inside
`src/components/WorldMap.vue`, and add its sprite name to `TILE_DECO` in the same file when it should carry a
pixel-art decoration.
在 `src/game/terrain.js` 的 `TERRAIN` 里加类型，在 `src/components/WorldMap.vue` 的 `drawTile()` 里给它底色；若还需要装饰，把素材名加进同文件的 `TILE_DECO`。

A marker that should also appear on the minimap and the atlas goes into `src/game/atlas.js` — `drawMiniMap()` draws
the tiny version and `drawAtlas()` the draggable one, both from the same world state.
需要同时出现在小地图与全图上的标记请写进 `src/game/atlas.js`：`drawMiniMap()` 画小图、`drawAtlas()` 画可拖动的全图，两者读同一份世界状态。

Note that `TERRAIN_KEYS` order is the serialisation order used by `gridToIds()`, so append new terrain at the end
or old saves will read the wrong ids.
注意 `TERRAIN_KEYS` 的顺序就是 `gridToIds()` 的序列化顺序，因此新地形请追加到末尾，否则旧存档会读错 id。

### 新增战场地形 · Add battlefield terrain

The terrain of a **battle** is a separate table: `ARENA_TERRAIN` in `src/game/arena.js`. One record is enough —
it carries the colour the field is painted with, the speed, attack and defence modifiers it applies and whether
a soldier may walk on it. `generateArenaTerrain()` places the kinds on the field, `damageOf()` reads the ground
under the fighters and `BattleMap.vue` paints the cells.
**战场**的地形是另一张表：`src/game/arena.js` 里的 `ARENA_TERRAIN`。加一条记录就够——它带着这块地皮的颜色、
它给出的速度 / 攻击 / 防御修正，以及士兵能不能走上去。`generateArenaTerrain()` 负责把这些地形摆到战场上，
`damageOf()` 读取交战双方脚下的地形，`BattleMap.vue` 负责把格子画出来。

```js
myterrain: {
  key: 'myterrain',
  name: '沼泽',
  en: 'Marsh',
  color: '#5c6b3a',
  speedMul: 0.6,   // 移动变慢 movement
  atkMul: 0.9,     // 攻击下降 attack
  defMul: 1.05,    // 防御上升 defence
  walkable: true,
  note: '沼泽：移动 −40%，攻击 −10%，防御 +5%。'
}
```

A kind that is not walkable must never stand where an army deploys: `generateArenaTerrain()` clears the
deployment columns, and a soldier that gets stuck behind water is nudged sideways in `stepBattle()`, so a fight
can never stall.
不可通行的地形不能出现在军队的出发位置上：`generateArenaTerrain()` 会清空出发区域，而被水挡住去路的士兵
会在 `stepBattle()` 里被侧向推开，因此战斗不会卡住。

### 新增难度 · Add a difficulty

The difficulty table is `DIFFICULTIES` in `src/game/difficulty.js`. A record carries the key, the names, the icon
and `rewardDelta`: how much gold a correct exam answer loses on that difficulty. The reward formula reads it
through `rewardFor(question, difficulty)`, so a new difficulty needs no other change — but it should also be
added to the two pickers (the home screen and the world map sheet) if it is meant to be visible.
难度表是 `src/game/difficulty.js` 里的 `DIFFICULTIES`。一条记录包含 key、名称、图标以及 `rewardDelta`：
该难度下每答对一题少拿多少金币。奖励公式通过 `rewardFor(question, difficulty)` 读取它，因此新增难度不需要改
其他地方——但若要让人看到它，还需要把它加进两个选择器（首页与世界地图的难度面板）。

### 版本与更新内容 · Version and changelog

The version and the update notes live in `src/game/versions/`: `index.js` exports `VERSION`, `VERSIONS` / `CHANGELOG`
and the helpers, one file per release (`v0.0.1.js`, …) holds the batches of that release, and `batches.js` is the
generated list of every shipped batch.
版本号与更新内容都写在 `src/game/versions/`：`index.js` 导出 `VERSION`、`VERSIONS` / `CHANGELOG` 与辅助函数，
每个发布版本一个文件（`v0.0.1.js` …）写着这次发布的批次，而 `batches.js` 是所有已发布批次的生成结果。

Releasing a new build is three edits:
发布一个新版本只要动三处：

1. raise `VERSION` to the next patch number — `nextPatchVersion(VERSION)` gives it, and only the last digit moves;
   把 `VERSION` 改成下一个修订号（`nextPatchVersion(VERSION)` 可以算出来，目前只加最后一位）；
2. add a release file `v0.0.2.js` (with its `version`, `date`, `title`, `summary` and `batches`) and list it in
   `VERSIONS`;
   新增一个发布文件 `v0.0.2.js`（写上 `version`、`date`、`title`、`summary` 与 `batches`），并把它加进 `VERSIONS`；
3. write the shipped work down in `progress.md` and run `node tools/build-versions.mjs` to regenerate
   `src/game/versions/batches.js`, then note the release in `README.md`.
   把这次的工作写进 `progress.md`，运行 `node tools/build-versions.mjs` 重新生成 `src/game/versions/batches.js`，
   再在 `README.md` 里记一笔。

Nothing else has to change: the home screen reads the module, so the badge and the update notes follow the number
on their own.
其它地方都不用动：首页读的就是这个模块，版本号与更新内容会自己跟着变。

### 题库扩展 · Question mods

Every subject is a **mod**, the five built-ins included, and both paths use the same contract — so adding a
subject never touches `ExamModal.vue`, the reward formula or the save format.
每个科目都是一个 **mod**（五个内置科目也一样），两条扩展路径共用同一套契约——因此新增科目不需要改 `ExamModal.vue`、奖励公式或存档格式。

A mod is one object (JavaScript) or one JSON file:
一个 mod 可以是一个 JS 对象，也可以是一个 JSON 文件：

| 字段 Field | 必填 Required | 说明 Meaning |
| --- | --- | --- |
| `key` | 是 Yes | 唯一 id，正则 `[a-z0-9-]`，同时作为题目的 `type` 与存档 key 前缀。Unique id (`[a-z0-9-]`), also the question `type` and the save-key prefix. |
| `name` | 否 No | 中文界面名。Chinese label. 缺省用 `key`。 |
| `en` | 否 No | 英文名。English label. |
| `icon` | 否 No | 一个 emoji，考试界面的科目按钮用。One emoji for the subject button. |
| `grades` | 否 No | 适用年级，默认 `[3, 4]`。Supported grades, `[3, 4]` by default. |
| `items` / `questions` | 否 No | 声明式题列表（两个字段名等价）。Declarative question list (the two names are aliases). |
| `kinds` | 否 No | 生成器函数 `(grade) => [{ kind, make(rng, grade) }]`，只能写在 JS 包里。Generator templates, JavaScript packs only. |

At least one valid item or one generator is required, otherwise the pack is rejected.
至少有一条合法题目或一个生成器，否则整个包会被拒绝。

Each declarative item is:
每条声明式题目包含：

| 字段 Field | 必填 Required | 说明 Meaning |
| --- | --- | --- |
| `id` | 是 Yes | 包内唯一且**永不变更**：它就是记忆曲线的 key。Unique in the pack and **never renamed** — it is the memory-curve key. |
| `grade` | 否 No | `3` 或 `4`，缺省取 `grades[0]`。`3` or `4`, defaults to `grades[0]`. |
| `prompt` | 是 Yes | 题干。Question text. |
| `options` | 是 Yes | 至少 2 个互不重复的非空选项；超过 4 个时只取正确答案加 3 个干扰项。At least 2 unique non-empty options; extras beyond four are dropped. |
| `answer` | 是 Yes | 正确选项的下标（从 0 开始）。Zero-based index of the correct option. |
| `explain` | 否 No | 答错时显示的解析。Shown under a wrong answer. |

```json
{
  "key": "safety",
  "name": "安全常识",
  "en": "Safety",
  "icon": "🚦",
  "grades": [3, 4],
  "questions": [
    {
      "id": "electric-shock",
      "grade": 3,
      "prompt": "发现有人触电，首先应该怎么做？",
      "options": ["直接用手去拉他", "先切断电源", "站在原地大声呼喊", "用水泼向他"],
      "answer": 1,
      "explain": "先断电再施救，否则自己也会被电到。"
    }
  ]
}
```

**External pack · 外部题库包** — drop the file into `public/mods/`, then list it in `public/mods/index.json`:
将文件放进 `public/mods/`，再在 `public/mods/index.json` 里登记：

```json
{ "mods": ["safety.json"] }
```

`main.js` calls `ensureModsLoaded()` at boot and the exam awaits the same promise before drawing a paper, so a
large pack cannot produce a short paper; each file may hold one mod or `{ "mods": [ … ] }`.
`main.js` 在启动时调用 `ensureModsLoaded()`，考试出卷前会等待同一个 Promise，因此大题库包不会导致卷子题目不足；每个文件可以是一个 mod，也可以是 `{ "mods": [ … ] }`。

Registration is first-wins: a duplicate `key` is rejected, a file that fails to parse is skipped, and the built-ins
are always registered before any external pack. To try a pack without writing a file, paste it in the console:
注册是先到先得：重复 `key` 会被拒绝，解析失败的文件会跳过，内置科目永远先于外部包注册。想不落盘就试一个包，可在控制台执行：

```js
kidsWarGame.loadModsFromText('{"key":"my-pack","name":"我的题","grades":[3],"items":[{"id":"a1","prompt":"1 + 1 = ?","options":["1","2"],"answer":1}]}')
```

**Built-in generators · 内置生成器** — `english.js`、`math.js`、`logic.js`、`chinese.js` export a type table
(`ENGLISH_TYPES` etc.); add a function there and it becomes a `kind` of that subject automatically. `fn.name` is
the stable kind, so it is also the memory key — renaming a generator resets its curve. `encyclopedia.js` is
declarative and demonstrates the item path.
`english.js`、`math.js`、`logic.js`、`chinese.js` 各导出一张题型表（`ENGLISH_TYPES` 等），往里加一个函数就会自动成为该科目的一个 `kind`。`fn.name` 既是稳定的 kind，也是记忆 key——重命名生成器会让这条曲线归零。`encyclopedia.js` 是声明式写法，可作为题目路径的范例。

Every generator must return the `choice()` shape (`prompt`, `options`, `answer` index, `explain` optional),
because the exam UI and the reward formula read only those fields; `choice()` keeps at most three distractors, so
every question has 2–4 options.
每个生成函数必须返回 `choice()` 的形状（`prompt`、`options`、答案下标 `answer`，`explain` 可选），因为考试界面和奖励计算只读这些字段；`choice()` 最多保留 3 个干扰项，因此每道题都是 2–4 个选项。

The Chinese bank shows the two shapes a bigger subject needs. `POEM_BANK` holds one record per poem (title,
author, dynasty, theme and the lines), and every poem question is generated from it, so a new poem only means a
new record. `PASSAGES` holds the reading passages, each with its own questions; the passage text is prepended to
the prompt, and the exam styles the question box with `white-space: pre-wrap` so the passage keeps its breaks.
语文题库展示了大型科目需要的两种写法。`POEM_BANK` 每首诗一条记录（诗题、作者、朝代、主题与诗句），
所有古诗题都由它生成，加一首诗就是加一条记录；`PASSAGES` 存放阅读短文与各自的题目，
短文会被拼进题干，考试界面的题目框用 `white-space: pre-wrap` 保留换行。

A generator needs a **bank of at least four items**, otherwise a paper would repeat the same prompt; the
`tools/verify-chinese.mjs` check enforces that.
每个生成函数的题库**至少要有四条**，否则一份卷子会重复出题；`tools/verify-chinese.mjs` 会守住这条线。

### 新增势力 · Add a faction

Add it to `FACTIONS` and `NPC_FACTIONS` in `src/game/factions.js`; `buildParties()` will then spawn its warbands
clustered around anchors automatically.
在 `src/game/factions.js` 的 `FACTIONS` 和 `NPC_FACTIONS` 里加一项，`buildParties()` 就会自动围绕锚点成团生成它的部队。

### 新增设施 · Add a facility

Facilities live in `FACILITIES` in `src/game/settlement.js`. One entry is enough: the town panel renders the list
from that table, `facilityCost()` prices the next level, and the effect is read by the systems that care about it
(the hospital by `healRate()` and `survivalChance()`, the barracks by `armyBonusOf()`).
设施写在 `src/game/settlement.js` 的 `FACILITIES` 表里。一条记录就够：城镇面板按这张表渲染，
`facilityCost()` 负责算下一级的价钱，效果则由关心它的系统读取（医院给 `healRate()` 与 `survivalChance()`，
军营给 `armyBonusOf()`）。

A new facility therefore needs three things: the table entry, a line in the effect table above, and the place
that reads it — for example `battle.start()` already adds `world.armyBonus` to the attack and defence of the army.
因此新增一种设施需要三件事：表里加一条、上面那张效果表加一行，以及真正读取它的地方 ——
例如 `battle.start()` 已经把 `world.armyBonus` 加到全军的攻击与防御上。

### 存档兼容 · Save compatibility

Anything added to the world state must also be written in `persistGame()` (`src/composables/gameState.js`) and
read back in `loadGame()` (`src/game/save.js`), otherwise it will be lost on reload.
任何加进世界状态的数据，都必须在 `persistGame()`（`src/composables/gameState.js`）里写出，并在 `loadGame()`（`src/game/save.js`）里读回，否则刷新后就会丢失。

## 15. 常见问题 · Troubleshooting

**地图点不动 / The character does not move.**
目标可能落在水域或孤岛上；此时会走到最近的可达位置。若完全没反应，请确认点击落在 canvas 上（顶部状态栏和图例会挡住地图）。
The target may be water or an island; the character then walks as close as possible. If nothing happens at all,
check that the click landed on the canvas rather than on the status chips, the minimap or the legend.
目标可能落在水域或孤岛上；此时会走到最近的可达位置。若完全没反应，请确认点击落在 canvas 上（顶部状态栏、小地图与图例会挡住地图）。

**天数不动、敌人也不动 / The day counter and the enemies are frozen.**
这是设计如此：游戏时间只在主角移动或扎营时流逝，站着不动会冻结世界。想让时间前进，点地图移动，或点「⛺ 扎营」。
By design: game time only advances while the lord walks or camps, so standing still freezes the world. Move by
tapping the map, or tap 「⛺ 扎营」 to let time pass in place.

**据点页签是空的 / A settlement tab looks empty.**
升级 / 考试 页签若整块空白，通常是某个面板组件在渲染时报错并中断了整个页面的更新（历史上就是 `UpgradePanel.vue` 漏了 `unitSprite` 导入）。打开浏览器控制台看 `[Vue warn] Unhandled error during execution of render function` 定位到具体组件即可。
A blank 升级 / 考试 tab usually means a panel component threw during render and aborted the whole page update — historically `UpgradePanel.vue` calling `unitSprite` without importing it. Open the browser console and look for `[Vue warn] Unhandled error during execution of render function` to find the component.

**升级后兵种没变，还是原来的兵种 / A promoted soldier keeps its old type.**
升级连线必须自带目标兵种：`upgradesFor()` 返回的每条边都要有 `type`（目标家族）与 `tier`（目标档位），因为界面和 `player.upgradeTroops()` 都只按这两个字段匹配。历史上边里只有家族记录的 `key` 而没有 `type`，于是「全部是民兵」时点任一分支（长枪兵 / 弓箭手 / 骑兵）实际写入的是一个 `type` 为空的兵员，界面按未知兵种回退成民兵显示，价格也退化成 8 金币保底价。`unitDef()` 现在会补上 `type: base.key`，可在控制台执行 `upgradesFor('militia', 1)` 确认三条边都写明了目标家族。
An upgrade edge has to name its target family: every entry returned by `upgradesFor()` needs a `type` (target family) and a `tier` (target rank), because the panel and `player.upgradeTroops()` match on exactly those two fields. Historically the edge carried only the family record's `key` and no `type`, so with an all-militia warband tapping any branch (spearman / archer / cavalry) stored a soldier with an empty type that the UI fell back to militia for, at the 8-gold floor price. `unitDef()` now supplies `type: base.key`; run `upgradesFor('militia', 1)` in the console to confirm all three edges name their target family.

**进不去城镇 / Cannot enter a town.**
需要走到据点约 1.4 格以内，底部才会出现「进入」按钮。
You must be within about 1.4 tiles of the settlement before the "enter" button appears.

**强盗的村庄进不去 / A bandit village cannot be entered.**
这是设计如此：强盗控制的村庄禁止进入，底部按钮会变成「⚔️ 赶走强盗」，打赢驻军之后村庄就变成无主，可以进入。别的势力的城镇可以直接进去（考试、招募都行），想据为己有才需要「🏰 准备围城」等 2 天再「⚔️ 攻打」；无主的城镇如果没人防守就「🚩 占领」，有人守军则要「⚔️ 攻城」打下来。
That is by design: a bandit village is closed to the lord, so the bottom button becomes 「⚔️ 赶走强盗」 — win against the garrison and the village turns unclaimed and open. A town held by a kingdom can be entered without a fight, and only has to be stormed if the lord wants to own it: prepare a siege for two days, then storm it. An unclaimed town nobody defends is claimed with 「🚩 占领」; one that still holds soldiers has to be taken with 「⚔️ 攻城」.

**无主的城镇为什么不能直接占领 / Why can I not claim an unclaimed town right away.**
因为城里还有守军。按钮会变成「⚔️ 攻城」并显示守军人数，把守军打下来城镇才归你；打输了城镇还是原样，可以再来一次。地图上那些没有守军角标的无主城镇才能直接「🚩 占领」。
Because the town still holds soldiers. The button becomes 「⚔️ 攻城」 with the number of defenders, and the town is yours only once they are beaten; a lost assault leaves the town as it was and you may try again. An unclaimed town without a garrison badge on the map can be claimed with 「🚩 占领」 right away.

**围城一直没准备好 / The siege never becomes ready.**
围城准备需要 2 天，而时间只在移动、扎营、城镇休整或**准备围城**时流逝——准备期间时钟会自己走，所以站在原地等也是有效的。
The preparation takes two days, and the clock only runs while the lord marches, camps, rests in a settlement or **prepares a siege** — so standing still is enough, the siege keeps the clock alive.

**想中断围城 / I want to call off a siege.**
准备期间（以及准备完成之后）底部都有「🚫 取消围城」按钮，点它即可中断：准备进度作废，时钟也停下来。
While the siege is prepared — and after the preparation is over — the bottom bar carries a 「🚫 取消围城」 button; tapping it calls the siege off, the preparation is lost and the clock stops again.

**攻打失败后还能再打吗 / Can I storm the town again after losing?**
不可以。攻打失败会中断这次围城，必须重新「🏰 准备围城」等满 2 天才能再次进攻——这样失败是有代价的。
No. A failed assault breaks the siege: the lord has to prepare it again (two more days) before he may attack a second time, so a defeat costs something.

**战斗太快看不清 / The battle is too fast to follow.**
战斗默认是慢速（🐢）。想更快就把战斗界面右上角 ⚙ 打开，切到 🚶 正常或 🐇 快速；想慢下来同理。
The battle runs slow by default (🐢). Open the ⚙ tools in the corner of the battle screen to switch to 🚶 normal or 🐇 fast, and back again whenever you like.

**战场只看得到一小块 / The battlefield does not fit on the screen.**
战场比手机屏幕大，镜头会跟着战斗走。用手指拖动可以自由查看，点 🎯 让镜头回到战斗；两军靠近时镜头会自动拉近。
The field is bigger than a phone screen, so the camera follows the fighting. Drag it with a finger to look around, tap 🎯 to bring it back, and it zooms in on its own when the armies meet.

**伤兵一直不恢复 / The wounded never heal.**
行军时每点每天只恢复 6 点生命，城镇里是 24 点，自己的城镇更快，医院还会再乘一次。伤兵会带着剩余生命进入下一场战斗。
Marching restores 6 hit points a day, resting in a settlement 24, your own town even more, and a hospital multiplies the rate again. A wounded soldier carries its damage into the next battle.

**队伍空了怎么办 / My warband is empty.**
敌对部队会暂时不再攻击你；走到最近村庄用金币招募民兵即可恢复（金币来自城镇考试）。
Hostile parties stop attacking you; walk to the nearest village and buy militia (gold comes from town exams).

**敌人打不完 / Enemies keep appearing.**
这是设计如此：被击败的部队会从地图移除，其余部队继续游荡，世界不会主动补充新的敌人。
By design: defeated parties are removed, the rest keep roaming, and the world does not spawn replacements.

**新势力的部队图标是空白 / A new faction's party icon is blank.**
在 `factions.js` 里加了势力却忘了重新生成素材：将领素材是按 `COMMANDERS` 和 `factions.js` 的配色画出来的，运行 `node tools/pixel-assets/generate.mjs commander` 即可。
A faction added to `factions.js` without regenerating its art leaves the party icon blank: the commander sprites are painted from `COMMANDERS` and the colours in `factions.js`, so run `node tools/pixel-assets/generate.mjs commander`.

**新增的题库不出现 / A new question mod does not show up.**
检查 `public/mods/index.json` 是否列出了文件名、`key` 是否与已有科目重复（重复会被丢弃），以及每条题目是否都有唯一的 `id`、非空 `prompt`、至少两个互不相同的选项和合法的 `answer` 下标——不合法的题会被静默丢弃。也可以在控制台用 `kidsWarGame.loadModsFromText(json)` 直接验证一段 JSON。
Check that `public/mods/index.json` lists the file, that the `key` is not already taken (duplicates are dropped), and that every item has a unique `id`, a non-empty `prompt`, at least two distinct options and a valid `answer` index — invalid items are dropped silently. You can also validate a JSON blob directly with `kidsWarGame.loadModsFromText(json)` in the console.

**分享的二维码打不开 / The shared QR does not open.**
确认对方和你在同一个 WiFi 局域网，并且打开的是本机的局域网 IP 而不是 `localhost`。
Make sure the other device is on the same WiFi LAN and that you shared a LAN IP, not `localhost`.

**进度丢了 / Progress is gone.**
存档按领主名字隔离；用同一个名字在同一个浏览器上「继续上次进度」即可。
Saves are keyed by player name; pick the same name in the same browser and use "continue".
